## Comunicación

El canal principal de comunicación del equipo será WhatsApp. 

Los integrantes se comprometen a mantener una comunicación activa durante el desarrollo del TCI, informando avances, dudas, bloqueos y cualquier situación que pueda afectar las tareas acordadas. 

Las reuniones de trabajo se realizarán de manera presencial o virtual cuando el avance del proyecto lo requiera, coordinándolas previamente por el grupo de WhatsApp. 

## Convención de commits

Utilizaremos Conventional Commits para mantener un historial claro y consistente.

Principales tipos:

- `feat:` nueva funcionalidad.
- `fix:` corrección de errores.
- `docs:` cambios en documentación.
- `chore:` tareas de mantenimiento o configuración.
- `refactor:` cambios internos que no agregan funcionalidades ni corrigen errores.

Ejemplos:

`feat: agrego búsqueda de expedientes`

`fix: corrijo validación de usuario`

`docs: actualizo CONTRIBUTING`

## Pull Requests

Todo cambio deberá realizarse mediante una rama y posteriormente ingresar a `main` mediante un Pull Request.

Reglas:

- No se permite realizar `push` directamente sobre `main`.
- Cada Pull Request deberá ser revisado por al menos un integrante distinto de su autor.
- El autor de un Pull Request no deberá aprobar ni mergear su propio PR.
- Los títulos de los Pull Requests deberán describir claramente el cambio realizado.
- Antes de realizar el merge se verificará que el cambio funcione correctamente y no introduzca conflictos.

## Protección de main

La rama `main` se utilizará únicamente para versiones estables del proyecto.

Los cambios ingresarán a `main` exclusivamente mediante Pull Requests revisados por otro integrante del equipo.

## Definition of Done

Una tarea se considerará terminada cuando:

- Cumpla con el objetivo planteado.
- El código o documentación esté completo y sea comprensible.
- No introduzca errores conocidos.
- Se encuentre actualizado con la versión correspondiente de `main`.
- Se haya creado el Pull Request.
- Otro integrante haya revisado y aprobado el cambio.
- El Pull Request haya sido mergeado a `main`.

## Participación del equipo

Todos los integrantes se comprometen a participar activamente y cumplir con las tareas acordadas.

Si un integrante no puede cumplir con una tarea o con los tiempos acordados, deberá comunicarlo al equipo lo antes posible para poder reorganizar el trabajo.

Si existe una falta de participación reiterada, el equipo conversará internamente para conocer la situación y redistribuir las tareas. Si el problema continúa y afecta el desarrollo del TCI, se informará al docente.
